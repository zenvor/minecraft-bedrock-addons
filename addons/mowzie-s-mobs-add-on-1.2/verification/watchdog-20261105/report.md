# Mowzie's Mobs Watchdog 调查记录

## 结论

2026-11-05 00:41 的 28.606 秒 Watchdog，最有证据支持的候选根因是 Mowzie 脚本的实体注册表长期保留已失效实体：注册表会随实体加载、区块卸载不断增长，注册事件和三个周期任务又反复线性扫描整个数组，具备把一次 `dataDrivenEntityTrigger` 处理拖入 Watchdog 的条件。

故障后 BDS 已重启，脚本堆内数组没有写入世界备份，因此无法恢复故障瞬间的精确数组长度；现有日志也没有事件 ID、实体类型或更深堆栈，不能证明 Watchdog 一定发生在 `register` 分支。该判断来自故障栈与时间线、脚本数据流及调用路径的一致性，仍需部署后的长期观察，或记录事件 ID、实体类型和注册表长度的低开销诊断，才能确认直接根因。

## 证据

- 正式服日志在 `2026-11-05 00:41:20.589 +08` 记录 Mowzie `InternalError: interrupted at _0x47c8db (main.js:1)`；`00:41:20.595 +08` 随即记录脚本线程已挂起 28606 ms。该时间窗没有内核 OOM 记录，BDS 以状态 6 退出后由 systemd 重启。
- `_0x47c8db` 是 `dataDrivenEntityTrigger` 分发器；Mowzie 实体的 `register` 事件会调用 `_0x1e049e`，后者先由 `_0x1ed77d` 线性扫描注册表，再把实体加入 `_0x8acd20`。
- `_0x3aab40` 原实现只把失效实体 ID 写入 `_0x353147`，没有从 `_0x8acd20` 删除实体引用。实体正常卸载不会触发死亡清理，因此数组会跨区块加载周期累积。
- `_0x172abf` 每 tick、`_0x591a8b` 每 5 tick、`_0x3aab40` 每 20 tick 遍历同一个数组。积累同时放大注册事件和常驻 tick 成本。
- `controller.animation.hf_mzs.def.register` 从默认状态无条件进入 `reg`，并在进入时执行 `@s register`。实体重新加载后已有注册路径，不需要在脚本数组里永久保留失效引用。

## 修复

- `_0x1ed77d` 改为反向遍历，在每次注册或死亡清理时同时移除失效条目、同一对象及同 ID 的重复包装；`_0x1e049e` 随后只加入当前实体。这样注册事件不会把旧垃圾带入下一轮，也不会因对象包装不同而重复登记同一实体。
- `_0x3aab40` 在执行现有更新前反向删除 `undefined` 或 `isValid() === false` 的条目。反向删除可处理相邻失效条目，不会跳项；随后只遍历有效实体，并移除已经失去用途的 `_0x353147` Map 与重复有效性检查。
- `_0x4b2e12` 对投射物及其 projectile 组件使用可选链，只有确实取得攻击者时才写入 `hf_mzs:last_attacker`。环境伤害仍会进入受伤状态，但不会再因读取空攻击者 ID 抛出异常。

没有增加容量上限、超时、缓存或新的事件订阅，也没有改包版本、清单 UUID 或正式服。

## 排除项

- 雕刻师伤害处理 `_0x4b2e12` 的空攻击者 `TypeError` 确实存在，但本次对应日志发生在 `2026-11-04 23:22:59.791 +08`，比 Watchdog 早约 78 分钟，不是同一次同步调用。它作为独立的已确认异常一并修复，不作为 Watchdog 根因证据。
- 脚本中还存在大范围方块搜索等高成本路径，但静态调用路径不能把它们连接到这次被中断的 `_0x47c8db`，因此没有据此扩大修改范围。

## 本地校验

- `node --check` 通过。
- Terser 完整解析通过。
- `verify-fix.mjs` 直接从当前混淆源码提取修改后的函数并执行：注册时会清除失效项、`undefined`、同 ID 旧包装和重复对象，只保留无关有效实体及当前注册实体。
